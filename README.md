# Trip · наше место для двоих

Android-приложения Вани и Наташи + веб-версия. Версия 2.4.0.

## Первый запуск

1. В приложении Вани нажать **Создать наше место**. Старый код не нужен.
2. В редакторе открыть **Подключить Наташу → Создать код подключения**.
3. В приложении Наташи нажать **Подключить приложение** и ввести короткий код. Код действует 15 минут и используется для одного устройства. Повтор запроса с того же устройства безопасен.
4. После подключения приложения помнят своё пространство. Прежние приватные ключи также работают; существующие данные остаются в пространстве `legacy`.

Для веб-редактора: `https://ivan-s-2001.github.io/trip/?app=husband`. Ссылка с кодом подключает браузер, поэтому для фоновых Android-уведомлений код нужно ввести именно в APK Наташи.

## Сообщения

Редактор: текст до 20 000 символов, до 10 фотографий и одно голосовое, немедленная или отложенная отправка по Москве. Фотографии сжимаются перед загрузкой; каждое вложение до 1 МБ. Доступны письмо, подарок, удержание, объятия и выбор ответа. Подготовленные собственные материалы доступны в редакторе.

Получатель видит ленту сообщений, переключает их свайпом или кнопками. Уже полученный список доступен без сети; новые медиа требуют подключения. Черновик редактора и очередь ответов сохраняются локально. Доставленные сообщения нельзя редактировать; будущие можно переносить и отменять.

## Интерфейс 2.4

Редактор с предпросмотром, локальным черновиком и дополнительными настройками вложений. Получатель видит одно письмо, может открыть список всех сообщений, увеличить фото и повторить загрузку вложения. Статус связи показывает, когда доступны только сохранённые письма. Правила оформления: `design-system/TRIP.md`.

## Доставка через ntfy

Используется открытый API [ntfy](https://github.com/binwiederhier/ntfy). Через `ntfy.sh` проходит только строка `sync` в случайном канале длиной 14 символов. Ключи доступа, текст, названия, фотографии, голосовые и ответы туда не отправляются. Сигналы не кэшируются на ntfy. Каналы `up` используют документированное ограничение по подписчику ntfy: лимит относится к получателю, а не ко всем приложениям с общим IP Cloudflare. До первого подключения получателя ntfy может вернуть 507; сообщения остаются на Trip и догружаются при подключении. Знание канала не даёт доступ к содержимому: приложение загружает данные с Trip API по своему ключу.

Android получает JSON stream ntfy в foreground service; при восстановлении соединения и каждые 5 минут догружает пропущенные сообщения. Во время работы видна тихая постоянная системная карточка связи. Повторные сигналы не создают повторных уведомлений. Веб-версия слушает SSE при открытом приложении; фоновые уведомления в PWA не реализованы.

Cloudflare Worker хранит очередь доставки в D1. Немедленная отправка запускает обработку через `waitUntil`, отложенная — cron раз в минуту. Поэтому для отложенного системного уведомления возможна задержка до минуты плюс доставка сети. Ошибки ntfy повторяются с увеличением интервала. Если ntfy недоступен, содержание всё равно сохраняется и догружается напрямую. Фоновая работа Android зависит от разрешения уведомлений и энергосбережения устройства; принудительно остановленное приложение нужно открыть снова.

## Сервер

Cloudflare Workers + D1. Все сообщения, медиа, события и состояния изолированы по пространству. Создание нового пространства не предоставляет доступ к существующему. Сервер хранит хеши ключей и одноразовых кодов.

`server/schema.sql` — схема новой базы. `server/migrations/002_rooms_ntfy.sql` — однократная миграция базы 2.2.1. После неё выполнить `003_subscriber_push.sql` и `004_standard_push_topics.sql`. Повторно миграцию 002 не выполнять. `server/wrangler.toml` включает cron `* * * * *`. `python server/build.py` формирует Worker с веб-ресурсами.

## Проверки

Node 24:

```sh
node tests/server.test.mjs
node tests/messages.test.mjs
node tests/rooms-push.test.mjs
node tests/migration.test.mjs
node tests/sync-auth.test.cjs
```

Из родительской директории:

```sh
node trip/tests/sync.test.cjs
node trip/tests/content.test.cjs
```

GitHub Actions публикует веб-версию и собирает APK Вани и Наташи после изменения `main`.

Проверка UI в реальном Chromium с синтетическими данными, без обращения к серверу: `node tests/ui.browser.cjs`. Требуется доступный модуль Playwright; при необходимости задать `TRIP_PLAYWRIGHT_MODULE` и `TRIP_CHROMIUM`. Проверяются предпросмотр без отправки, черновик, загрузка/удаление вложения, отправка, ответы, удержание, офлайн, ширины 375/1440 px и альбомная ориентация.
